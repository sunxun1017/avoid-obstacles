# G1 势场 PPO 与 DAgger 训练设计

日期：2026-10-08。状态：设计与实施计划已确认，实现已验收；命令见 `docs/field_training.md`。
替代此前“速度跟踪策略与 AMP 接入”设计；本次不实现 AMP、在线建图或单点速度导航方案。

## 用户目标与交付

用户要求使用 Unitree G1，依照 Collision-Free Humanoid Traversal 的方法使用势场，
训练场景专用策略，再用 DAgger 蒸馏通用策略。项目应可上传服务器，安装依赖后通过明确命令训练。
完成标准为真实仿真中的 PPO 与 DAgger 优化、保存、加载和恢复经过短训练验证；不是声称已经收敛。

## 依据与复现边界

- 论文版本：[arXiv:2601.16035v2](https://arxiv.org/html/2601.16035v2)。
  公式 1--5 定义势场及身体优先级；公式 6 定义多身体点观测；公式 7--10 定义 vMF 方向奖励。
  III-B2 使用 PPO 训练 specialists，再通过 DAgger 蒸馏 generalist。
- 作者源码：[Click-and-Traverse](https://github.com/GalaxyGeneralRobotics/Click-and-Traverse/tree/866ba392f1c1e84b92ad75fa66550f26e8af8e48)，
  固定提交 `866ba392f1c1e84b92ad75fa66550f26e8af8e48`。
  已阅读 `env_cat.py`、`constants.py`、`train_ppo.py`、`train_ppo_dagger.py`。
- 论文写 K=13；已核对公开源码定义头、骨盆、躯干、双脚、双手、双膝、双肩共 11 点。
  可运行 G1 配置默认采用这 11 个具名点，明确标记为公开源码点位配置；不杜撰论文缺少定义的两个点。
  点位 schema 可配置，未来核实完整 13 点定义后可单独配置；不宣称 11 点与论文完全相同。
- 默认使用论文公式观测和 vMF log-likelihood 奖励，不将公开代码的方向余弦窗口称为公式 10。
  点位数量、动作自由度、基础行走奖励、场景规模及后端迁移都在训练指南中记录为复现差异。
- 本次是方法级复现与可训练基础工程，不交付原论文全场景/全规模实验或成功率结论。

## 训练数据流

```text
声明式场景几何 + 目标候选集
  → 离线体素障碍/SDF/测地距离场，附场景哈希
  → mjlab 中由同一几何配置创建实体和接触
  → G1 世界系身体点位置/速度（减去环境平移原点）
  → 论文势场与优先级 → 多身体点观测及方向奖励
  → PPO specialist checkpoint（一个场景对应一个教师）
  → 学生访问多个场景 → 对应教师标注 → 数据聚合/监督更新
  → DAgger generalist checkpoint → 独立评估
```

不读取深度相机，不调用 OccupancyMapper。环境几何是已知的，地图原点和仿真障碍必须一致。
场构建在准备阶段完成；训练步骤中不执行 CPU Fast Marching。
每个场景提供多个预计算目标场；reset 从合法目标和起点中采样，训练不固定单一目标。
不同环境使用各自 scene_id、goal_id；不以第一个环境的场和教师替代整批。

## 模块边界

| 目录 | 职责 |
| --- | --- |
| `perception` | 论文公式、字段查询、稳定 vMF 数值函数；不读机器人或仿真器 |
| `data` | 场景/目标场缓存与 DAgger 聚合数据；持久化元数据 |
| `robots` | G1 身体点和关节 schema；有名、有序、可校验 |
| `tasks` | 场景选择、观测、奖励、终止规则的组合 |
| `simulators/mjlab` | 已知障碍几何、G1 状态、原生动作及训练后端适配 |
| `algorithms` | PPO 后端入口及通用 DAgger 采集/更新，只通过环境和专家契约访问数据 |
| `policies` | 冻结教师与学生网络、归一化和推理 |
| `cli` / `configs` | prepare、ppo、dagger、evaluate 入口及声明式配置 |

通用公式、数据集和 DAgger 不导入 mjlab。仿真器只在应用构造时导入。
本机验证后端为 mjlab 1.6.0、rsl-rl-lib 5.4.2、Torch 2.7.1；服务器安装约束明确锁定兼容版本。
复用官方 PPO 后端，不重新手写 PPO。公开代码只学习或有限改编，保留相应出处、许可证和修改说明。

## 观测、动作与奖励

- 点位位置/速度 `[B,K,3]`，统一世界/场景坐标后计算公式 1--5，根部基础权重 1，其他点 0.5。
- 策略输入包含本体状态、上一动作、多身体点势场，保持确定的点位和关节顺序。
  世界向量旋转到重力对齐的机器人 yaw 坐标系；不把身体俯仰当成导航坐标变换。
- critic 可以使用额外状态；DAgger 标签时教师获得与训练时相同的观测及归一化。
- G1 原生关节位置动作、尺度与 PD 由 mjlab 机器人配置负责；元数据记录动作关节和尺度。
  不声称此配置与作者动作布局完全相同。
- 默认场奖励按公式 10：`sum(log C3(kappa) + kappa * dot(mu, velocity_unit))`。
  `kappa=0`、零场、零速度、远距离、接近障碍均须有限，明确零速度不被当作正确对齐。
  小距离势场正则沿用已有 min_distance 切线延拓，并记录其工程性质。
- 加入目标推进/到达、跌倒/碰撞及基础稳定性、关节限位、能耗和平滑项，权重全部配置。
  不保留会强制站直、从而阻止下蹲的强姿态约束；避免方向奖励鼓励站着不动或贴墙。
- 物理地面作为接触支撑，与禁入障碍区分；不把正常落脚视作障碍碰撞。
- 碰撞、跌倒、到达、越界/无效场、超时单独定义与记录；timeout bootstrap 使用后端语义。
- 身体点速度从原生运动学状态计算；reset 不跨 episode 有限差分。
  奖励与终止使用 reset 前状态，下一步观测使用 reset 后新场景/目标。

## PPO 与 DAgger

PPO：一个场景专用 run，目标候选集随机化；训练噪声/扰动与基础课程可配置。
日志包含各奖励、到达率、碰撞/跌倒率、目标距离；保存 actor/critic/优化器/归一化/迭代及环境配置。
resume 校验场景哈希、schema、网络、动作布局，拒绝不兼容模型，不能静默加载部分权重。

DAgger：加载多个场景教师，按当前环境的 scene_id 路由对应教师。
学生驱动访问状态，冻结教师给确定性动作标签；初期可按显式 beta 混合教师执行，默认 beta 逐轮衰减到零。
无论实际执行哪个动作，保存当前学生观测与当前教师标签；不能只收集教师轨迹并称为 DAgger。
聚合旧轮与新轮数据，使用有容量限制的采样库监督拟合教师动作。
学生网络和归一化与 checkpoint 一起保存；恢复包含聚合数据、优化器、轮数、beta 调度及随机状态。
评估使用纯学生，不调用教师动作控制；教师与学生动作契约必须一致。

## 可携带配置与训练命令

交付三类以上小型场景（绕行墙、窄通道、低横梁/地面障碍），物理与体素几何同源，附初始/目标合法性检查。
不下载 3D-FRONT 私有/授权数据，不依赖本机绝对路径；用户可用同一 schema 扩展场景。
入口拟为 `python -m embodied_learning.cli.field_training` 的 `prepare`、`ppo`、`dagger`、`evaluate` 子命令。
最终训练指南给出完整安装和命令：准备所有场景，逐场景训练教师，再从教师清单启动 DAgger。
教师清单直接引用实际生成的 checkpoint，不使用虚构预训练权重。
默认日志用本地文件/TensorBoard，不要求 W&B 登录；支持 seed、device、num_envs、iterations、resume。
训练时长与环境数为工程配置，不能把小规模命令当作原论文规模复现。

## 验收证据

1. CPU 数值测试：vMF 与显式公式一致，稳定极限、方向排序、身体优先级、坐标变换及掩码。
2. 场景测试：实际障碍与离线网格一致、起点/目标可达、场缓存 schema/哈希检查。
3. DAgger 测试：教师路由、学生状态标注、聚合、冻结教师、beta、save/resume 等价。
4. 实际 CUDA mjlab：多环境 reset/step、有效势场、物理障碍接触、episode 终止隔离、奖励有限。
5. 两个不同场景真实短 PPO 更新，参数发生变化，生成可加载的 checkpoint，恢复训练成功。
6. 使用上述两个 checkpoint 实际 DAgger 更新，聚合数据增长、学生参数变化、恢复成功、纯学生评估可运行。
7. 检查最终文档每条训练命令和参数均由真实 CLI 支持，依赖和场资产随项目可安装/生成。

真实避障效果和收敛需要服务器长训练评估，验收报告将明确区分运行证据与策略能力。
