# 感知到运动控制及 AMP 接入设计

日期：2026-10-08。状态：待用户审阅；尚未开始产品代码实现。

## 目标与分阶段范围

用户希望把已有建图/势场观测接入机器人运动，保持感知、策略、算法和仿真器解耦，并参考 AMP 开源实现。
采用之前确认的顺序：先通过已有速度跟踪策略跑通势场到行走的控制链路，再加入 AMP 训练。

第一阶段交付通用速度指令生成、策略接口、mjlab 外部指令项、严格的原生 checkpoint 加载入口、组合示例及测试。
第二阶段交付机器人特征契约、参考动作采样、AMP 判别器/回放/归一化与奖励混合，以及 PPO 后端集成。
第一阶段不会把随机/零动作测试描述为已经实现自主行走；第二阶段不会把合成数据的损失测试描述为学会动作。

当前 `policies`、`algorithms`、`tasks` 仍是空模块；项目目录未发现 `.pt`/`.onnx` 权重或动作 `.npz`。
已经向用户请求本机策略与动作数据路径。缺少资产不阻止接口和数值测试，但真实行走与 AMP 收敛验证需要对应资产。

## 第一阶段数据与依赖边界

```text
传感器适配器 → RayMeasurements → OccupancyMapper → 地图快照
                  应用显式重建势场 → 引导向量/有效掩码
                  tasks：引导 + 机器人位姿 + 目标 → 速度指令
                  simulators/mjlab：外部速度指令项 → 原生观测
                  policies：冻结策略 → 原生关节动作
                  mjlab：动作缩放、关节目标、PD 与物理步进
```

计划职责：

| 位置 | 责任 |
| --- | --- |
| `protocols/policy.py` | 推理与按环境重置契约，不导入具体后端 |
| `tasks/navigation.py` | 纯 Torch 引导到速度指令，不读取仿真器或调用场构建 |
| `simulators/mjlab/commands.py` | 外部速度缓冲、原生命令项和配置，仅本层依赖 mjlab |
| `simulators/mjlab/locomotion.py` | 按官方 runner/任务配置加载 checkpoint，提供策略接口 |
| `examples/mjlab_field_locomotion.py` | 显式组合地图、场、目标、策略与环境步进 |

算法不直接依赖感知或仿真器；感知不直接生成关节动作。原生策略保持已训练的观测与动作布局。
不把势场向量直接送入只接受本体状态/速度指令的旧策略，也不任意拼接输入以改变其维数。

## 通用速度与策略契约

导航转换接收世界系引导 `[B,3]`、有效掩码 `[B]`、根部位置 `[B,3]`、四元数 `[B,4]`（wxyz）及目标 `[B,3]`。
输出体坐标系速度 `[B,3] = [vx,vy,wz]`，单位 m/s、m/s、rad/s，另返回指令有效状态。
速度与转向限值显式配置，并必须在实际冻结策略的训练范围内。
无效/不可达引导、非有限数据、目标达到、水平零向量输出零速度指令；这不保证机器人物理安全停住。
世界到体坐标使用重力对齐 yaw，避免把俯仰/侧倾当作导航角度。
第一阶段处理平面导航，不把 Z 向引导转换为下蹲/跳跃，也不声称具备窄门或横梁的全身通过能力。

策略接收后端原生观测，返回 `[B,A]` 动作；推理使用 eval/no_grad。
加载时严格核对任务、关节顺序、动作尺度、观测特征/归一化、历史顺序和网络配置。
不匹配时给出错误，不回退到随机策略。优先使用本机 mjlab 官方 runner 的 load/get_inference_policy 路径。
无 checkpoint 的显式测试模式仅用于接口/指令时序探测。
循环在 episode 结束时重置策略历史、导航状态、对应地图和缓存势场；策略的 recurrent reset 由对应适配实现承担。

## mjlab 指令时序

本机 mjlab 1.6.0 源码显示：step 中先计算奖励/结束状态，随后执行 command_manager.compute，再生成下一步观测。
普通 UniformVelocityCommand 会随机重采样、应用 heading/standing/world 标志；直接写其 command tensor 不足以保持外部控制。

新增外部命令项持有 `pending_command` 和当前 `command`：

1. 策略从返回观测中读取当前指令，产生动作。
2. 应用根据当前传感器/位姿生成下一周期指令，仅写 pending 缓冲。
3. env.step 执行动作，奖励仍使用与该动作观测一致的当前指令。
4. 命令项在原生 compute 阶段提交 pending，原生环境生成带新指令的下一步观测。

导航指令有明确的一个控制周期延迟，不额外重算观测历史，也不改写观测张量中的硬编码切片。
首次 reset 的当前/pending 指令都是零；自动重置的环境只清理自己的缓冲。
外部命令项保留 checkpoint 原有命令名、维数和观测缩放，关闭内部随机指令覆盖。
地图/场的更新频率独立于控制频率；未更新时使用明确的缓存快照，不能将上个 episode 的快照继续用于新 episode。

## 第二阶段 AMP 约束与接入方式

AMP 是训练期间的风格奖励与判别器学习机制；部署时执行 actor，不运行判别器优化。
参考 MimicKit 的 BCE 变体作为明确命名的算法模式，另有原始论文最小二乘模式时使用独立配置和测试，不能静默更换奖励公式。

- 判别器输入为机器人运动特征的时间窗口 `[N,L,F]`，`L>=2`，按明确的时间顺序展平。
- 特征包含哪些身体/关节由机器人特征契约定义；策略与示范必须使用同一 schema、关节顺序、坐标系和采样时间间隔。
- 不把地形图、目标坐标或任务奖励混入 AMP 风格特征，避免判别器用场景差异代替动作风格判断。
- `robots` 负责状态到特征的编码，仿真器负责读状态，`data` 负责动作片段与合法窗口采样。
- 数据窗口不能跨动作片段边界，也不能拼接自动重置前后的状态。
- 判别器模块、标准化器、策略样本回放和优化器属于 `algorithms/amp`，只接收张量/数据接口。
- 使用同一标准化状态处理示范、当前策略和回放样本；更新时机与 checkpoint 保存/恢复明确一致。
- 风格奖励从 detached 判别器输出计算，与任务奖励按显式权重相加，再交给 PPO 后端。
- 在采集端明确获得 reset 前终止状态或选择手动 reset；不假定 step 返回的自动重置观测就是终止运动状态。
- 参考数据必须说明机器人、关节/身体名、特征 schema、帧率、许可和来源；不自动把其他机器人的动作视作可用 G1 示范。

真实第二阶段开始前需要确定可用数据与特征契约。重定向动作、恢复策略、动作生成器、长时间训练和实机部署属于后续明确任务。
